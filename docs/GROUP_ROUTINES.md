# Bot 与群聊 Routine

`v0.3.0-beta.42` 本地实现候选。Routine 将保存的指令发送到 Bot 或群聊的 **MAIN 主会话**，复用现有 SendWorker / RoomCoordinator。群目标属于真实 Room 主会话，不借用某位成员的私聊。本单元不支持 TASK 目标、事件订阅或 Webhook。当前源码、隐藏界面、安装包、跨平台及发行门禁分别记录，完整状态以[实施记录](IMPLEMENTATION_PLAN.md)为准。

## 在界面中创建与编辑

打开 **设置 → 主动服务**，填写名称和任务提示，在“执行目标”中选择 Bot 或群聊主会话。计划支持一次、间隔及带时区的五段 Cron。新任务创建为暂停状态；核对后启用，或用“立即运行”执行一次。计划依赖本机应用、所选模型连接和实际权限；它不是远程常驻调度服务。

群聊默认选中 **Everyone · 保存当前全部成员**。保存的是当时全部成员的固定名单；六位成员通过原有群聊路径并行执行，一个成员慢响应或等待审批不会阻塞其他成员。选择“只运行勾选成员”可保存明确子集；至少选择一位成员。这两种路由均不额外启动协调者 Handoff 链。

编辑器和已保存的卡片显示主会话代次、固定名单、成员版本和 Routine 定义版本。群目标提交已审阅的 `expectedMembershipVersion`，后端在保存时与真实成员版本比较。刷新列表不会把新成员自动加入原名单，也不会替换正在编辑的草稿。成员增加、移除、移除后重新加入或所选成员配置变化时，旧目标失效；立即运行和重新启用被阻止。

点击 **编辑 → 重新选择并审阅目标**，读取当前主会话和成员，再核对名单并保存。Everyone 重新选中当前全体；原来的指定子集保留仍在群内的成员，新成员不会自动勾选。重新选择本身不保存、更不启动任务。保存前界面再次读取目标，成员版本在提交前变化仍会被后端拒绝。版本或授权冲突保留本地草稿，用户需审阅当前版本后再保存。

当前编辑器不提供资料／媒体选择器。已保存的固定引用会显示数量；在同一主会话编辑时保留原引用，更换主会话会明确提示并清空该 Routine 的固定资料及媒体引用。AI 创建或更新时可以提交已授权的明确引用。成员加入群聊不会带入其私聊资料、Memory、环境或浏览器登录态。

## 固定范围与审批

保存目标时记录会话代次、授权版本、成员版本、所选成员配置及明确资料／媒体版本。运行另存当时的名称、提示词、计划、目标、授权快照和原始 nonce。之后编辑 Routine 或资料正文，不会改写已接受的运行及原引用。

授权撤销、资料停用或删除使旧授权失效；随后重新启用不会让旧运行获得新权限。当前实现保守比较 MCP 配置和凭据指纹，凭据轮换或刷新也可能要求重新选择目标后保存。密钥和完整内部授权明细不进入公开的 Routine / RoutineRun 数据。

界面与连接的 AI 使用同一业务校验。AI 经 `product_catalog → product_describe → product_execute` 发现并调用 `routines.list`、`listRuns`、`create`、`update`、`setEnabled`、`runNow`、`cancelRun` 和 `delete`。AI 只能操作当前 MAIN 会话的规则与运行，不能借目录访问其他聊天或 TASK。修改、启停、删除和取消使用当前 `expectedVersion`；新界面立即运行提交 `{ id, expectedVersion }`，审批后定义变化会使旧请求失效。兼容的旧字符串立即运行入口仅保留给可信宿主调用。

Routine 不会自动批准工具调用。文件写入、电脑、应用外发等仍遵守各自权限、固定参数审批及结果核验。模型说“已完成”不会替代真实回执；未知外发结果应先查询原请求。

## 状态、取消与恢复

“最近运行”显示宿主实际返回的状态；点击“刷新”重新读取持久记录。

| 状态 | 含义与界面行为 |
| --- | --- |
| 待处理 / 等待中 | 已登记，尚待派发或当前会话空闲；可取消本次运行 |
| 正在派发 / 运行中 | 正在接受或已有所属 Runtime / Room batch；可取消本次运行 |
| 正在取消 | 已请求取消，等待真实结束；不提前显示“已取消” |
| 已完成 / 失败 / 已取消 | 已有终态；显示实际错误，不自动重试 |
| 错过执行时间 | 该计划没有执行；不追补所有历史触发 |
| 结果未知 | 无法确认接受回执；先核验原 nonce 与实际执行情况，不自动重放或重发 |

**暂停 Routine** 阻止未来计划触发；**取消本次运行** 只停止该运行登记的 Runtime 或 Room batch。群取消针对该批成员，不杀其他聊天、独立规则或已有后台服务；等待中的运行可直接取消。接受期间的取消同样保留，不允许晚到的新 batch 越过取消请求。

运行记录在提交消息前持久化；相同内部触发 key 复用原始回执，不同请求摘要不能复用该 key。重启遇到“正在派发”时，仅检查原 nonce、消息来源、正文、引用和真实 Runtime / Room 接受回执；找不到或不一致便标为“结果未知”，不重放。原规则已有活跃运行时，重叠的计划产生“错过执行时间”，不阻塞其他规则。应用正常退出先等待正在接受的派发，再关闭执行器。

## 后续事件桥接与支持边界

宿主内部保留 `createTriggerRun(input, eventAttachment?)` 和触发回执查询，作为后续事件收件箱的基础。事件附件不属于公开 schema，不通过产品工具或 Renderer 提交。它必须是名称为 `automation-event.json`、MIME 为 `application/json` 的 UTF-8 JSON，真实大小不超过 64 KiB，大小与 SHA-256 均经核验。事件内容只进入不可信附件通道；消息正文仍是保存的 Routine 指令，附件不构成操作批准。

内部桥接存在不代表已接入事件来源。当前没有 HTTP 监听、Webhook、第三方事件订阅、TASK 自动化或云端常驻调度；这些能力另行实现和验收。
